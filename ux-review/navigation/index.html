UX review / Navigation design

How guests find their way.

Four peer sections: Arrival, Your stay, Explore and Help. Your stay is the landing page, with a room-first information catalog. A By room / By category switch reorganizes the same information inside this section. There is no separate Home page above the tabs.

      On a phone

      A persistent bottom bar: Arrival, Your stay, Explore, Help. Detail content scrolls above it. The selected section has an underline and a programmatic current state.

      On a desktop

      The same four destinations move to the header. Your stay shows its topic links beside the content. Labels and order stay consistent.

      Go deeper, then return

      Breadcrumbs show the page’s place in the guide. Back returns to the last page visited. Both Help controls preserve this return path. Arrival, Your stay and Explore start a new section journey. Only detail pages have parent links. A named parent link opens its own section. Section landings have no parent breadcrumb; these tabs are peers.

      Open a link directly

      A shared link opens that topic immediately. A detail opened directly uses its parent for the in-guide Back action. A section opened directly has no in-guide Back control. All four sections remain one action away. In the final guide, normal browser Back follows browser history.

      Reviewer tools: scenarios and direct links

      These controls belong to this review, not the guest interface. Opening a scenario or selecting Arrival, Your stay or Explore starts a new section journey. Both Help controls preserve a return path to the current page. Your stay retains its catalog position while moving between sections; a fresh load starts By room. Links within the content keep a local history.

      This prototype changes pages inside the frame. Its Back button tracks rehearsal history. The final guide will use real links and browser history. No operational instructions or external contact actions are implemented here.
